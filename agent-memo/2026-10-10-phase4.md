# 2026-10-10 Phase 4 implementation memo

## Implemented

- Kept the room participant registry keyed by room ID and session ID, with per-participant mute and PTT state.
- Audio is fanned out only to other participants in the same room, and only while the sender is unmuted and has PTT active.
- Participant state is broadcast after join, room switch, mute/PTT changes, explicit leave, and disconnect so clients can update the roster.
- Reduced each participant's bounded audio queue from 8 packets to 3 packets (up to 180 ms at the 60 ms compatibility frame size) to limit queued latency under congestion. Full queues drop new packets via `try_send`.

## Verification

- `cargo check` passed after the room state broadcast changes.

## Remaining validation

- Test 3–5 concurrent clients on a real network for audio stability, jitter, queue saturation, and disconnect isolation.
- Current full-queue behavior drops the newest packet; if congestion testing shows stale audio backlog, consider a latest-frame queue policy.
- Browser WebCodecs Opus support and microphone/playback behavior still require browser/device validation.
