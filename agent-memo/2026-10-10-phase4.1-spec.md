# 2026-10-10 Phase 4.1 specification change

## Goal

- Replace the browser/PWA custom WebSocket protocol with Socket.IO using Rust `socketioxide` and browser `socket.io-client`.
- Define distributed room communication across multiple Logger processes.
- Keep the Logger's URL-based room selection and remove the `room.join` event from the browser protocol.

## Decisions recorded

- Browser connection uses a Socket.IO namespace derived from the room URL: `/{room_id}`, with the transport path fixed at `/socket.io/`.
- The Logger derives the room from the namespace and joins it during connection setup. Room switching changes the namespace URL and reconnects; no `room.join` event is sent.
- Audio packets are sent as binary Socket.IO event payloads. Event names and payload schemas, error handling, reconnect state resynchronization, and transport settings must be specified during implementation.
- Use the requested `socketioxide-redis` as the intended cross-process adapter for room membership/state, control events, and audio fan-out. Before implementation, verify crate compatibility/API with the selected `socketioxide` version and confirm whether all required binary audio payloads are propagated. Do not silently treat process-local state as distributed state.
- Browser clients can retrieve a Logger server list via HTTP API or Socket.IO event and choose a connection target. Define the list source and fields (server ID, display name, URL, availability/status), plus authentication and exposure policy, before implementation; never return secrets in the list.
- Enable `socket.io-client` automatic reconnection after connection loss. Define retry/backoff behavior and UI connection states. After reconnect, re-establish authentication and namespace/room membership, then resynchronize `room.state` and participant status.
- Define behavior if the selected server stays unavailable: either try other listed servers automatically or retain the user's selection and offer a manual switch. If automatic failover is selected, it must work with the shared Redis-backed room state and must not create duplicate/stale participant state.
- The Pi compatibility endpoint `/ws/audio/{room_id}` remains on the existing raw WebSocket protocol and is outside this browser migration.

## Scope boundary

- This is a specification-only change. No runtime code or dependency files have been changed.
- Implementation starts after user review.
